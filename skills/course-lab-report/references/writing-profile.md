# 写作规则与课程适配

## 归纳依据

这份规则来自提供者选定的 7 份匿名历史报告，归纳共同的写作倾向，并区分课程模板带来的差异。来源编号和读取范围见 [版式与来源](layout-and-sources.md)。规则后的定位用于核查，不是要求新报告引用旧实验。

## 稳定的共同习惯

### 用问题引出方法

报告通常先交代要解决的具体困难，然后说明为何采用下一种工具或分析。例如，手动裁剪工作量大引出模型构建器；总体频数不足以解释城市差异引出分组；极端房屋可能影响相关引出敏感性分析；节点数增加后误差回升引出节点分布与数据精度的讨论。

写作时把“采用方法”与“解决问题”放在相邻句中，不需要反复标注“研究意义”“思考目的”。依据：S1 P0016—P0020，S3 P0061，S4 P0157，S6 P0189。

### 操作具体，解释有轻重

菜单、字段、参数和文件名与实验对象直接对应；重要步骤说明数据意义和检查方式。例子包括空间连接的合并规则、0/1 图线掩膜、高程字段、SPSS 拆分状态，以及程序输入配置。普通重复操作会引用前文或简写，判断步骤则展开。

据此，步骤写成“做什么—关键设置—如何检查”的短段；解释段承担“为何这样做”。不要把每次点击都扩成同样长的理论说明，也不要只保留操作清单。依据：S1 P0154—P0170，S2 4.3—4.5，S4 3.2—3.5。

### 让图表和正文共同完成解释

截图承载过程证据；统计表、误差表和结果图承载比较。正文明确指出读者要关注的字段、位置、变化和数量。图前常说明目的或设置，图后解释现象；但也有先给结果再放图、成组截图共用分析的写法，因此不固定唯一顺序。

结果段的常见思路是“当前结果—相对变化—意义—适用条件”，实际只写必要部分。避免把表中全部数字逐行重复，更适合挑能支持结论的数字，再解释差异。依据：S3 P0087—P0094，S4 P0124—P0132，S6 P0097—P0107，S7 PDF 物理第 5—10 页。

### 用对照和检查支持判断

样本会把数学性质、理论值、原始地图或第二种算法变成检查依据：同样本比较零阶相关和偏相关；保留与过滤极端样本并列；同节点数比较节点分布；迭代与递归输出互相核对。验证与当前问题紧密关联，不是为了增加章节数量。

说明对照改变了什么、保持了什么，以及结果能支持到什么程度。两种算法一致是支持实现正确的证据之一，不自动证明算法所有方面都正确；同样，截图不单独证明所有动态交互或所有测试均通过。依据：S1 P0339—P0343，S4 P0223—P0224，S6 P0189—P0193，S7 PDF 物理第 10—11 页。

### 实验思考呈现认识如何改变

较有个人辨识度的内容，是从真实问题展开的推理：短线并不一定无效，二维叠合并不保证坐标定义正确，大相关系数未必统计显著，节点更多未必误差更小。正文会说明原先怎么想、遇到什么证据、为何调整，以及以后应怎样处理。

“我认为”“对我而言”“这个例子使我认识到”可用于确有依据的判断。不要让所有段落都以“我”开头，也不要新编“最初失败了多次”“通过反复尝试”等经历。依据：S2 6.1—6.5、7，S4 5.1—5.3，S6 1.2.3、1.4.3。

### 正式而可理解，保留必要限定

文字主要是解释性的学生实验报告，术语与自然语言并用。例如把复杂方法说清楚，再回到本实验的字段和结果。样本经常区分相关与因果、总量与密度、几何显示与真实精度、实际完成与后续计划。

保留会改变结论的限定条件。对于已经明确的事实直接陈述；不要把所有结论写得犹豫，也不要为了“去 AI 味”机械删除连接词、并列项、正式术语或正常的反例说明。

## 不同课程的结构

| 类型 | 优先采用的组织方式 | 不要照搬的结构 |
|---|---|---|
| GIS 软件操作 | 目的与数据 → 原理/路线 → 操作与过程分析 → 成果 → 具体问题与思考 | 每个点击都写长篇理论，或只堆截图 |
| 地理建模与统计 | 问题与变量 → 方法条件 → 初步图形 → 主分析 → 必要的对照/分组 → 有范围的结论 | 只抄输出表和显著性星号 |
| WebGIS 系统设计 | 需求 → 架构与数据 → 关键实现 → 实际运行 → 测试与不足 | 把功能愿望写成已完成功能；强行改成纯操作教程 |
| 科学计算 | 题目与输入 → 算法/公式 → 实现要点 → 数值表和曲线 → 误差解释/对照 | 只贴代码或只给答案；每一题重复完整公共算法 |
| C++ 调试 | 环境与理论 → 断点/变量/调用栈观察 → 对象或算法行为 → 输出/边界用例 → 改进方向 | 用单张终端图代替过程解释 |

## 样本中的变体与改进边界

- S1/S3 有较密集的截图记录，S2/S4 的“步骤+解释”更完整；建议优先借鉴后两者的分析组织，但不把这解释为用户已经指定唯一范文。
- S5 的摘要、需求、架构与测试属于系统设计语境；S7 有正式封面和目录；这些不是所有实验报告的固定要求。
- S6 中“创新”有任务背景，不能据此规定每份报告必须声称创新。扩展分析应该实际完成且有帮助。
- S1 的临时截图备注、S6 的章节错序与相邻重复解释，属于后续可改进的编辑问题，不是应当模仿的特征。
- 风格档案不复核历史报告的全部技术主张。复用具体方法时，应按本次数据和软件重新确认含义。

## 无法动笔时的起草入口

先整理本次已有的实验对象、实际操作、最主要结果和遇到的问题。优先从材料最充分的一个结果段起写，用真实图表说明观察，再补充形成它的方法与原因。最后写目的和总结，使它们与实际完成的工作对应。

如果只有截图，先辨认每张图是输入、设置、中间过程还是结果，并记录能够读出的内容；看不清的字段不猜。如果只有代码，先说明实现思路和预期输出，实际运行与测试结论等待日志或执行结果。用户说“按我的风格”不等于授权补造实验事实。
